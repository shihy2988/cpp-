## 三、递归的本质

递归就是函数调用自己，但每次调用都必须更接近结束条件：

```cpp
void countdown(int n) {
    if (n == 0) return;
    cout << n << endl;
    countdown(n - 1);
}
```

递归必须有两部分：

1. 递归出口：什么时候停止。
2. 递归关系：如何把大问题变小。

如果没有出口，函数会无限调用，最终导致栈溢出。

## 四、DFS 与回溯

DFS 像在迷宫里沿着一条路走到底，走不通再退回来。推箱子求解中，DFS 可以尝试各种操作，但必须保存和恢复状态。

```text
选择一个方向
如果合法：执行
递归搜索
撤销刚才的操作
尝试下一个方向
```

回溯的关键不是“盲目递归”，而是“做选择、继续搜索、恢复现场”。

## 五、BFS

BFS 使用队列，像水波纹一样一层一层扩散：

- 第 0 层：起点
- 第 1 层：一步能到的位置
- 第 2 层：两步能到的位置

在每一步代价相同的情况下，BFS 第一次到达目标时就是最短路径。

当前仓库的 `src/solver.cpp` 已提供基础 BFS 框架，核心结构是：

```cpp
queue<pair<int, int>> q;
q.push({start.y, start.x});
while (!q.empty()) {
    auto current = q.front();
    q.pop();
    // 扩展上下左右四个方向
}
```

## 六、贪心思想

贪心是每一步选择当前看来最好的方案。例如走向目标时，优先选择曼哈顿距离更小的格子：

```cpp
int distance = abs(x1 - x2) + abs(y1 - y2);
```

但要注意：局部最优不一定带来全局最优。推箱子中，离目标近的箱子可能被推到死角，所以贪心只能作为提示或启发，不能无条件相信。

## 七、二分思想

二分需要一个具有单调性的条件。例如判断“最多允许多少步时能不能完成”，如果步数上限越大，答案只会从“不行”变成“行”，就可以二分答案。

基本过程：

1. 设定答案范围 `left` 和 `right`。
2. 取中间值 `mid`。
3. 检查 `mid` 是否可行。
4. 根据结果舍弃一半范围。

## 八、Undo 撤销设计

使用 `stack<GameState>`：

```cpp
stack<GameState> history;
history.push(currentState); // 移动前保存
// 执行移动
// 按 U 时恢复 history.top()
```

栈是后进先出。最后一次保存的状态最应该先恢复，这正好符合撤销功能。

建议保存：

```cpp
struct GameState {
    Player player;
    vector<Position> boxes;
    int steps;
};
```

## 十、常见 Bug 与调试

### Bug 1：BFS 死循环

原因通常是没有 `visited` 数组。每个格子第一次加入队列时就标记访问。

### Bug 2：找到的路径不是最短

可能使用了栈代替队列，或者在不同层重复修改距离。无权图最短路应使用队列 BFS。

### Bug 3：撤销后箱子位置错乱

可能只保存了玩家位置，没有保存整个箱子数组。撤销必须保存完整游戏状态。
